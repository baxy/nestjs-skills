# Vitest Setup

Applies when `vitest` is in the project's `devDependencies`. It is the runner `nest new` generates for ESM projects on NestJS 12. The tiers, layout and naming come from `rules/test-organize-by-tier`; this file only covers how Vitest implements them.

## One config, one project per tier

`vitest.config.ts` at the package root declares each tier as a project, and the scripts pick tiers with `--project`. This replaces the generated `vitest.config.e2e.ts` and its `*.e2e-spec.ts` pattern: tiers are selected by directory, and every spec is named `*.spec.ts`.

```typescript
// vitest.config.ts
import { defineConfig } from 'vitest/config';

export default defineConfig({
  resolve: { tsconfigPaths: true }, // The @/ alias, read from tsconfig.json (Vite 8)
  test: {
    globals: true,
    root: './',
    projects: [
      { extends: true, test: { name: 'unit', include: ['test/unit/**/*.spec.ts'] } },
      { extends: true, test: { name: 'e2e', include: ['test/e2e/**/*.spec.ts'] } },
      { extends: true, test: { name: 'db', include: ['test/db/**/*.spec.ts'] } },
      { extends: true, test: { name: 'integration', include: ['test/integration/**/*.spec.ts'] } },
    ],
    coverage: {
      provider: 'v8', // @vitest/coverage-v8
      include: ['src/**/*.ts'],
      exclude: ['src/main.ts', 'src/**/*.module.ts', 'src/config/**'],
    },
  },
});
```

`extends: true` gives each project the root options (alias, globals). Without it, a project starts from an empty config and `@/` imports fail.

```jsonc
// package.json
"scripts": {
  "test": "vitest run --project unit --project e2e",
  "test:unit": "vitest run --project unit",
  "test:e2e": "vitest run --project e2e",
  "test:db": "vitest run --project db --no-file-parallelism",
  "test:integration": "vitest run --project integration --no-file-parallelism",
  "test:coverage": "vitest run --project unit --project e2e --coverage",
  "test:watch": "vitest --project unit --project e2e"
}
```

- `--no-file-parallelism` is the tiers' "one file at a time" switch (Jest's `--runInBand`). The database and integration tiers share state, so they need it.
- Coverage is measured in one run over the stack-free projects, as `test-organize-by-tier` requires.

## From the Jest examples in the rules

The rule examples use Jest's API. Vitest's `vi` object has the same methods, so translate them one-to-one:

| Jest | Vitest |
|---|---|
| `jest.fn()`, `jest.spyOn()` | `vi.fn()`, `vi.spyOn()` |
| `jest.clearAllMocks()`, `resetAllMocks()`, `restoreAllMocks()` | `vi.clearAllMocks()`, `vi.resetAllMocks()`, `vi.restoreAllMocks()` |
| `jest.useFakeTimers()`, `setSystemTime()`, `advanceTimersByTime()`, `useRealTimers()` | `vi.useFakeTimers()`, `vi.setSystemTime()`, `vi.advanceTimersByTime()`, `vi.useRealTimers()` |
| `jest.mock('pkg', () => ({ ... }))` | `vi.mock('pkg', () => ({ ... }))`; a default export must be returned as `default` |
| `jest.Mocked<T>` | `Mocked<T>`, imported from `vitest` |
| `--runInBand` | `--no-file-parallelism` |
| `projects` in a coverage config | `test.projects` and `--project` |
| `moduleNameMapper` for `@/` | `resolve: { tsconfigPaths: true }` |

## Points to know

- **Globals.** With `globals: true` and `"types": ["vitest/globals", "node"]` in `tsconfig.json` (both generated by `nest new`), `describe`, `it`, `expect` and `vi` need no import. Without them, import each from `vitest`.
- **`vi.mock` is hoisted** above the imports. A variable the factory uses must be created with `vi.hoisted()`, or it is still undefined when the factory runs.
- **`supertest` under ESM** is a default import, `import request from 'supertest'`; `import * as request` gives a namespace that cannot be called. Type the app as `INestApplication<App>` with `App` from `supertest/types.js`.
- **Decorator metadata.** Nest's dependency injection needs the `emitDecoratorMetadata` output. The generated config relies on Vite 8 applying it from `tsconfig.json`. If a provider's constructor dependencies come out `undefined` in tests only (older Vite, a custom transform), the transform drops the metadata: add the `unplugin-swc` plugin, as the NestJS docs describe.
